# Bridgy's Farm (Բրիջիի ֆերման)

A browser game that teaches JavaScript: students write code that drives a drone on a farm. Built for the user's programming school in Armenia (beginners aged 9–17). It takes the *concept* of The Farmer Was Replaced (TFWR), with its own design. It is live: real students play on it at https://robot-farmer.vercel.app/ (deploys from the repo).

This file is the summary of **all 10 chats in this folder** (2026-10-13 to 2026-11-12), rewritten on 2026-11-12 from the saved transcripts: the user's rules, a chat-by-chat timeline, and the history of each part of the game. `README.md` (overview), `config/README.md` (every config file, Firebase rules) and **`docs/ARCHITECTURE.md` (how the code works inside: boot, interpreter, names, saves, ranch, recipes for adding things; read it when a task touches those, and update it in the same commit)** have more detail. Plans live in `~/.claude/plans/`. Check this file against the code before relying on it.

## Working with this user

- **Ask first.** They like many clarifying questions before planning (big features got 40–48). Brainstorm, write a plan, wait for approval, then build.
- **Commit and push only when they say "push to git".** Branch `main`, pushed directly to `github.com/programmingschoolarmenia-droid/Robot-Farmer`.
- **Never commit the root PNGs** (the user's original pictures) or `untitled folder 12/` (unrelated). Stage with `git add -u` and add new source files by name. `CLAUDE.md`, `.vercelignore` and `desktop/` were never committed.
- **Keep updates small and careful.** They dislike complicated UI and over-engineered fixes; secondary explanations go behind a "?" button.
- **UI quality matters.** They rejected plain or cheap looks: a bare white market page ("I dont like ui at all"), a village background that didn't match the buildings (twice), a hand icon that "looks like a butt", a too-loud ranch card. Match the game's existing style and look at the result.
- **No emojis as pictures.** Use code-drawn pixel icons (`sprites.js` `icons()`, `icon()` in `dom.js`). Only ▶ ⏸ ⏭ ⏹ ⏱ ⚠ ✓ ✕ stay as text symbols.
- **Never erase students' data.** Any save or leaderboard format change must keep or migrate old data.
- **Report honestly.** Say what was and wasn't verified. They write in English, sometimes loosely; UI text is Armenian only and should stay simple.
- **A list means two jobs.** When they send a list of fixes and ask for suggestions: their list gets fixed; bad mechanics, bad balance and small improvements found on top go in a numbered list for them to choose from, not into the code.
- **"Do it now" vs "plan it":** when they say do it, do it; when they say "write in plan" (or say nothing about timing), add it to the plan and they execute it later (stated 11-11).

## Teaching rules (the game's point)

- Never give ready-to-paste code. There is no "Try it" («Փորձել» was removed); the last hint gives the steps in words. Lessons use small examples that are not the quest answer.
- Armenian transliterated command names are primary (`tnkel()`, `havaqel()`, `gnal(Aj)`, directions Verev/Nerqev/Aj/Dzax). English names still work but stay hidden. JavaScript keywords stay English.
- Transliteration: յ=y, ը=e, ղ/խ=x, ք=q, ծ=c, ճ=ch. Spelling matters (Buyser, Darchnaguyn, Badrjan). Keep old spellings as aliases in `config/aliases.json`. New code names go in the plan for approval before building.
- Research gates JS features. There is one short quiz per JS lesson (wrong answers explain, no penalty). The help book (`config/guide.json`) shows only unlocked items.
- Only Bridgy teaches. Student friends Erik and Nshan (photos of real students) speak only in the help menu: Nshan = «Ի՞նչ անեմ հիմա», Erik = «Հուշում տուր»; Bridgy appears first, then the student image fades in.
- Everything a teacher might change lives in `config/*.json`, checked by the validator in `js/core/config.js`.

## Tech

- Plain HTML/CSS/JS with no build step. Vendored Acorn and CodeMirror 5, no new dependencies.
- Run: `npm start` (`python3 -m http.server 8080`). Test: `npm test` (187 tests passing on 2026-11-13), browser check: `npm run play`, prices: `npm run balance` (the simulator; see «Our own crop rules»).
- Student code runs in a generator interpreter over the Acorn AST (`js/lang/`).
- `js/engine/` holds the rules, `js/ui/` the screens, `js/storage/account.js` the accounts, `config/` the data, `css/mobile.css` the phone layout.
- **Firebase over REST, no SDK.** Username maps to the hidden email `name@bridgys-farm.app`. Docs: `saves/{id}`, `players/{id}`, `deleted/{id}`, `orders/{id}`, carpets/likes. Keys are set in `settings.json` (`online`). With empty keys it falls back to one local browser.
- **There is no server, so clients are authoritative.** Scores and market limits can be cheated with browser tools; this is known and accepted.
- **The teacher publishes Firestore rules by hand.** When rules change, give the full text and update `config/README.md`. Register the `admin` account before publishing rules that use `isAdmin`.
- The player market uses atomic Firestore `:commit`, a save `rev` (rules refuse a lower one, so an old tab gets sent back to login) and error codes `stale`, `gone`, `hasOrders`.

Calling `h()`/`replaceChildren` with `null` renders the text "null", so append conditionally. Don't let local variables shadow imported helpers such as `icon` (that caused the freeze).

- **Never rebuild a button on a timer.** A button replaced between press and release loses its click; that was the "works after 2–3 clicks" bug. Redraw only when what is shown changes (a key, as in `village.js`, `researchTree.js`), write live numbers in place, and let timers wait for `isPressing()` (`dom.js`). Test with a program running, or nothing redraws.
- **Phone typing:** real keyboards compose a word, and CodeMirror only reads it about 80 ms after it ends. Any redraw before that (a resize, marks) wipes the word, and `inputRead` never fires. So go through `editor.refresh()`, check `wordOpen()`, and don't change the editor's height while typing. Test with `Input.imeSetComposition` on an Android user agent; real phone keyboards can't be tested from here.
- `.typing` means the editor has the focus, `.keyboard` that the keyboard is really open (`main.js`). The bars hide only with both.
- **After any editor layout change, look at the phone's Code tab:** the symbol keys must scroll to the last one and the console's clear button must show. `.code-panel` needs `minmax(0, 1fr)`, or its widest child stretches it.

### Our own crop rules, code order and balance (11-13, plan `sprightly-drifting-stroustrup.md`; not pushed yet)
The teacher's aims: less like TFWR (every farm rule and number was TFWR's 1:1), and a slower start. One update, pushed at once **on a Monday** (the weekly challenge's times change).
- **Code order:** Loops → Variables → Debug → Operators → Plant → Lists → Utilities → Functions → Objects; a crop comes after the JS it needs. Loops gives `while`; `for` also needs Variables (`gate.js`). Debug also gives `console.log` and `alert` (a Bridgy window that pauses the program; it has «Կանգնեցնել» so an endless alert loop can be left).
- **Rules** (numbers in `settings.json → entities`; details in `docs/ARCHITECTURE.md` §5):
  - Eggplant grows from `Irer.Sermer` (1–3 back per harvest; wheat drops one in 20 once the card is owned).
  - Apricot fruits 3 times (`chapel()` = fruits left). Mulberry `Buyser.Tteni` ×2 next to a ripe rosehip.
  - Watermelon: `hasunE()` only says it has grown; `chapel()` is its sweetness 0–100, under 80 a harvest gives nothing, 12 s after 100 it rots.
  - Yellow melon `Buyser.DexinDzmeruk` spreads by vines, one harvest takes the joined ripe ones (n²). Square melon `Buyser.QarakusiDzmeruk` has the giants (n³). All three follow the «Ձմերուկներ» levels.
  - Pomegranate: even ones in rising order pay a combo 1, 2, 3 …; an odd one spills a juice. `xmel()` drinks one juice: ×2 speed for 50 actions (nothing is automatic).
